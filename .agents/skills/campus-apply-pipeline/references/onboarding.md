# 资料复用与首次补充

## 先复用，后询问

依次检查用户指定路径、当前项目配置、已有投递档案及简历。优先读取已有资料；当前环境的档案真源是 `work/application_profile.json`，不要因某个约定文件名不存在，就重新询问姓名、教育经历等已确认内容。

当前环境若已有 `auto-resume-submit/config.json`：
- 简历路径、浏览器项目根、求职工作区根、看板地址由该配置读取，不另建冲突副本。
- 补充事实读取 `workspace_root/work/application_profile.json`。
- 其中 `confirmed_answers` 是用户确认事项，`resume_facts` 是简历提取事实。具体字段可使用 `{value, source, date, scope}`；先看实际结构，不假定另一个 schema。
- 最新用户明确确认优先于旧 PDF 与解析结果；同一优先级有冲突则询问。限定公司/岗位的答案只在该范围复用，例如某公司允许调剂不等于全国不限。
- 原 PDF 的内容与官网修正分开处理；用户只要求改表单时，不修改或替换附件。

只读搜索可以在非必需个人资料缺失时继续。投递时只询问实际必填、仍缺失或有歧义的事项；把相关问题集中提出，继续不依赖答案的工作。

## 没有资料时才创建档案

本工作区已有真源 `work/application_profile.json`，仅在没有可复用档案时才用 [模板](../scripts/profile.template.json) 新建，路径由用户指定或放在项目私有 `work/` 下。不要把模板当作真实候选资料，也不要把模板路径视为可上传文件。

分组收集实际需要的信息，不要求一次填写所有字段：
1. 简历路径、联系方式、教育及毕业届别；优先由简历提取供核对。
2. 岗位方向、排除条件、城市偏好及调剂意愿。
3. 当前所需的渠道登录、浏览器和记录工具配置。
4. 正在申请的表单新增必填项。

模板中的 `null`、空字符串、空数组都表示未知。国籍、学历、是否全日制、搬迁及调剂不能套默认答案；用户未说明城市限制也不能因此把异地一票否决。证件号码不进入模板，确有必填需求时交用户在该表单处理。

## 字段与范围

- `candidate`：经确认或可靠简历来源支持的事实；`language.score` 保存准确成绩，不用分数区间替代已知分数。
- `targets`：目标届别、角色红线、城市及去重政策。只投已核实适用于该届的批次，不能把「以后各届」默认视为合格。
- `sources`：指向既有配置/确认档案，避免复制后漂移；来源仍须可访问。
- `platforms`：现有浏览器和可选短信服务的连接信息；配置地址不是读取所有短信或启动新服务的授权。
- `bookkeeping`：实际存在的客户端或本地结果路径；没有看板客户端时写本地，不拼一个猜测的接口。

保存用户新确认时附来源、确认时间及适用范围，保留其他信息；更新已有档案即可，不强制维护两份事实副本。表单呈现约束（如技能白名单）不意味着从岗位评分资料中删除真实项目能力。

日期按官网粒度映射：已知完整日期可以填年月，只有年月不能补造某一天。预计入职日期落在过去、相对到岗时间需要换成具体日期、或与原答案明显冲突时，先询问，不自行改年份。

档案及候选个人材料不提交公开仓库；短信码、密码、验证码答案不写档案、脚本、日志或截图说明。截图只保留取证所需范围。

登录复用只需记录网站或企业租户、所用浏览器资料目录的标识、最近核验时间及登录/失效/未知状态；不复制浏览器资料，不保存或输出 cookie、会话 token 和密码。用户已有的不同浏览器登录状态不能视为相通。
