# 填表、提交与取证

只在投递授权范围内执行。环境、浏览器和账号的既有配置优先；不要为套用配方改用户环境。

## 1. 固定身份与断点

记录公司、岗位 ID/详情 URL、批次、申请页面及简历文件。读取本地断点、看板与官网应聘记录做去重；查不到与查询失败区分处理。用户换岗时更新这些标识，旧表单不能继续提交；已有申请修改保留原申请编号。

本地记录示例（不含简历内容、验证码或会话 token）：

```json
{
  "attempt_id": "本次尝试的唯一标识",
  "company": "公司",
  "position": "岗位",
  "job_id": "官网岗位标识",
  "job_url": "https://employer.example/job/id",
  "state": "draft",
  "proof": {},
  "dashboard_state": "not_written"
}
```

状态依次可为 `draft`、`needs_input`、`awaiting_verification`、`submitted`；不能确认结果时保留 `awaiting_verification`，明确排除用 `skipped`，技术阻塞用 `blocked`。继续任务时从断点核验实际官网状态，不从头重投。

## 2. 登录

按当前网站正常入口登录。验证码的「谁来做」按 [safety-gates.md](safety-gates.md)「验证码边界」判定（点选型可经可信点击完成并截图核对；滑块、短信、字符码交用户），失败一次即停。验证码发送一次后先观察倒计时/发送反馈；未发出与已发出未收到不是一回事。配置了且已获授权的短信服务才可使用，按 [安全规则](safety-gates.md) 检查验证码归属与新鲜度。不可用就请用户提供或手动登录。

验证码失败或频控按网站实际提示处理；没有明确恢复时间不要编造固定冷却期，不在后台循环发送、不静默等十几分钟。需要稍后处理时保存断点并说明恢复条件；用户请求稍后提醒才设置提醒。

正常验证码仅按当前工具许可的交互方式处理。工具要求用户接管、少量尝试仍未通过或出现风控时交用户；不用隐藏挑战实例、伪造 token、重放验证码或绕过验证 API。

出现「近期已投递/无法内推」先查记录，按去重规则处理。不能把切换直投作为绕过已有申请的方式。

## 3. 上传与解析

确认当前表单属于固定的公司及岗位、文件路径真实存在且已获授权。主表单可使用真实 `input[type=file]` 上传；iframe 上传器按网站正常流程再点上传。看到文件名还需区分仅选中与服务器已上传，结合上传反馈核验。

先盘点字段及所属区块、重复条目、frame、已有值和正式附件；有官网解析入口时按需启动，字段已有用户修订时先保存核对快照，避免解析覆盖。助手或解析结果不是事实来源：仅填语义明确且有来源的内容，与 PDF 及最新确认逐项比对，纠正误识别；本人、家人、联系人和不同学历不能串用。只改表单的要求不扩展为修改附件。

## 4. 真实控件填写与双轨修障

普通标准控件优先利用扩展进行快速初填；当遇到现代前端框架的 4 大硬墙（`isTrusted` 真实事件防作弊、文件上传沙箱、React/Vue 虚拟 DOM 与模型脱节、Portal 浮层/虚拟滚动）时，按 [cdp-form-remediation.md](cdp-form-remediation.md) 由 Agent 直接使用 CDP 执行物理事件注入（`Input.dispatchMouseEvent` / `Input.insertText`）、特权附件上传（`DOM.setFileInputFiles`）与浮层穿透。

- 使用字段 label、稳定字段标识及所在经历条目定位，避免同名字段串行填错。
- 点击前滚动目标到实际滚动容器的可见中部，待布局稳定。用 `elementFromPoint` 核对点击点确属目标或其子元素；被固定页脚/遮罩覆盖时先正常滚动或处理明确提示，不移除遮罩。
- 下拉先打开再读取真实可见选项，虚拟列表可以搜索/滚动；用正常选项点击或键盘确认。数字角标可能是岗位数，不是选项值。
- 日期按字段实际粒度输入或点面板，先读当前年月。已知完整日期可用于仅显示月份的控件，但不能把站点内部每月一日的占位值当成已确认日；若可见预览或记录暴露了错误的具体日期且无法更正，先停下询问。未知具体日、过去的预计到岗日期等按资料规则澄清。
- 核对日期、解析等疑点时只用安全的草稿查看/暂存及只读信息。唯一预览入口可能提交时，不能试提交来检查；若字段明确只收年月，按年月填并注明粒度。要求完整日期但无法确认正确值时，保存断点并说明未决问题。
- 每次切选项、增加/删除经历、解析、预览后复核关键值。用户给出技能白名单时仅限制对应表单技能项，不删除真实项目描述中的技术能力。
- 缺失必填集中询问，可选未知留空；不把模板中的国籍、学历、全日制或调剂默认值填给用户。

字段清空先检查真实输入事件、必填校验、选项联动和官网提示。不能仅凭一次失败断言「store 冻结」，也不能反复刷新、重传简历、试提交。定位后做有限恢复，仍不可保存就列出准确字段和值请用户接管。

## 5. 提交一次，再核验

先核对目标身份、授权与剩余数量、最新去重、必填及已可查看的值、附件、岗位/学历/城市等约束。**在最早可能提交的动作前**保存本地 `awaiting_verification` 断点：部分门户的「预览并提交」或完成验证码就会提交，不能假设一定还会有独立的最终确认按钮。按页面实际流程完成必要声明和一次提交；若该动作确实只进入预览，继续复核预览后再按正常流程确认。

后续验证码、成功跳转、页面白屏都属于这同一次尝试。异常时先只读查询该申请记录，不创建第二次尝试；只有官网已明确证明未提交，才考虑修正后的重试。再次发送仍须在原授权范围内；结果未知不重投。

证据强度与平台实际功能相适应：
- 优先核验应聘记录中的公司、岗位标识、提交时间/唯一申请编号，确认是这次新增申请，而不是旧记录或相似岗位。
- 有记录入口但暂不可读时保持待核验；若门户根本没有可用记录入口，可依据官方明确成功页、与目标公司/岗位的关联以及本次新增申请的唯一标识共同确认。通用成功文案或不能关联本次申请的旧编号不够，缺证据就保持待核验。
- 成功页正文/标题与 URL 共同核对本次岗位；请求返回 200、上传成功、解析成功或通用 agent `success=true` 均不够。
- 有截图能力时保留必要范围的截图（**提交后取证**按平台可用性；**填表自检**的整页截图是必做，见 `D:\auto-delivery\resume-autofill\SELF_LEARNING_LOOP.md` §3 第 4 步）；页面自动跳走则及时记录 URL/申请号并回查记录。没有配额功能的平台不强求配额减一，有配额时作为交叉核对。
- 成功后需要核实字段时进入同一申请的查看/编辑，不撤销、不重投。

## 6. 结果与看板

核验成功后才把本地状态置为 `submitted`。使用直写记录客户端（自 2026-10-28 起已无需看板助手对话，直接调用 REST API 直写）：调用 `qiuzhao_api.record_application(company, position, status="已投递", date=...)`（或兼容调用 `qiuzhao_api.record_submission(...)`），约 0.3s 原子写入 Excel 并刷新看板网页。

提交结果和看板回写分别记录。回写前查是否已有该申请，发出回写前记 `record_pending`，完成后回读核验再标为 `recorded`。回写超时保持待核实，先查询已有记录，再决定是否补记；申请已成功时绝不为了补看板重新投递。

中间态只保存在本地/对话，不写看板已投递或过程待办。汇报实际岗位、渠道、结果与证据链接；未公布的截止时间写未公开。

## 7. 质量门禁与任务协调

- **解析后四项强制质量检查（严禁带病提交）**：
  1. **教育经历**：必须独立保留两段（电子科技大学硕士 2024.09~2027.06 + 上海海事大学本科 2020.10~2024.06），学习形式统一为全日制。
  2. **实习经历**：华为技术有限公司（含端侧小模型与 A2A 协议两部分）与苏州科达科技股份有限公司（仅含后台码流检测 Multi-Agent 系统）必须两段独立，严禁跨公司混串截断。
  3. **项目经历**：必须拆分为两个独立卡片（卡片 1: `CC & Pi 架构的本地 Multi-Agent 编程助手` 2026.03~2026.06，链接 github.com/9ian9-218/claude-pi；卡片 2: `科研知识图谱 RAG 系统` 2025.12~2026.02，链接 github.com/9ian9-218/rag-fec），严禁将两项目挤压合并进单张卡片，严禁项目名与描述错位。
  4. **技能清单**：严格执行白名单过滤，只保留 Python 与 C++，清除 ATS 自动抓取的无意义碎片词。
  发现任何解析错位，必须在表单控件内完成编辑修正并核验无误后，才允许进入预览与提交。
- **多岗位配额与志愿排序**：遵照用户确立的 Base 优先级（江浙沪长三角 > 深圳 > 其他）与 JD 契合度综合决定多志愿排序；支持多岗位投递的公司在任务范围内尽量把配额投满。
- **并发协作与资源管理**：
  * 每个并发任务/subagent 必须绑定独占的标签页与断点，严禁跨页面干扰或争抢焦点。
  * subagent 严禁点击最终确认提交按钮，统一停在预览页由 Lead 执行四项质量核验。
  * **标签页生命周期**：投递完成并登记看板后，**必须立即关闭对应标签页**，释放浏览器内存与 CDP 句柄。
- **无匹配岗位的看板双向闭环**：全站核实无匹配岗位时，通过直写 API（`qiuzhao_api.update_application(company, status="终止")` 或 `upsert_job`）予以封锁，防止后续循环复活；具体原因如实向用户报告，不经对话接口。机制细节与解除封锁见 [screening-playbook.md](screening-playbook.md)「看板双向闭环」。
