# 平台故障排查

以下来自具体页面经验，先观察当前 DOM、提示及正常请求再判断；一个门户的症状不能推广为全平台结论。所有恢复服从 [安全规则](safety-gates.md)，提交结果未知时先查记录。

## 通用顺序

1. 核对公司、岗位 ID、当前标签与断点。
2. 检查数据是否加载齐全、是否有弹层、原生离开提示或固定页脚遮挡。
3. 对目标控件正常滚动、重新定位，检查命中点，再原生操作并读取结果。
4. 检查可见校验/联动提示；必要时只读观察该操作的正常网络响应，避免保存或输出 token、cookie、完整短信及无关个人资料。
5. 有明确新证据才换方法；同一故障最多做约 3 次有区别的诊断/恢复，仍不行保存断点并说明接管/恢复条件，不无限重试。

## 北森新版（phoenix）

| 现象 | 检查与处理 |
|---|---|
| 岗位详情空弹层 | 查当前卡片是否实际展开、按钮是否可见、是否另开标签；核验目标表单，而不是只看空层 |
| 看得到值但预览清空 | 查看官网字段联动和校验提示，检查相关教育/日期来源；先真实控件填写、失焦与预览回读，不调用私有 handler |
| 学习形式或毕业日期被自动更新 | 读取实际更新后的值。与用户确认冲突时继续核对来源；站点仍清空就如实标记该字段未完成，不把 DOM 初值当保存成功 |
| 下拉空白 | 先关闭已有面板重开，考虑虚拟列表及请求错误；多门户都复现只能支持平台故障的推测，不能据此编造根因 |
| 结束时间禁用 | 检查该条目的「至今」，通过正常复选框修正，并回读 |
| 预览或确认按钮无效果 | 检查声明、预览页独立隐私复选框、遮罩、必填提示、正常请求与验证码，不直接再次提交 |
| 短暂成功页 | 及时记录申请号/URL，回查真正的投递记录入口；不要把流程说明页当记录页 |

2026-10-27 实战踩坑与高频故障避坑清单（北森 Phoenix、北森 Classic、大易、Moka）：

- **北森 Phoenix 按钮点击机制**：立即投递、预览与提交按钮的外层容器 `.phoenix-button__wraper` 是真实绑定事件的节点，点击内层 `.phoenix-button__content` 文本往往无法冒泡触发 React 提交。
- **北森 Phoenix 日期分步展开**：点击日期 input -> 点击 `.phoenix-calendar-year-select` 年面板 -> 翻页选中年份 -> **必须再次点击 `.phoenix-calendar-month-select` 展开月份面板** -> 选中月份 -> 点击具体日。漏点月份会导致日期始终无法落值。
- **北森 Phoenix 地区树选择**：点击地区文字仅用于展开下级列表；真正选中必须点击 `.area-item-container` 内的 `.icon-container` 单选 svg，待底部显示「已选地区 1/1」后再点确定。
- **北森 Phoenix 单选状态**：组件为自定义样式，选中状态体现为容器 class 包含 `phoenix-radio--checked`，原生 DOM `input.checked` 属性往往不更新。
- **北森 Phoenix 期望月薪校验**：若控件底层要求数值输入，填入“面议”会触发红色状态错误 `请输入数值` 拦截提交；该字段为非必填，遇到数值校验时直接清空留空。
- **北森 Phoenix 技能清理与暂存陷阱**：ATS 解析出的无意义技能碎词若删除按钮失效，可直接将非目标技能的名称输入框清空，保留 Python 与 C++；填完技能后千万不要点“暂存”（暂存会导致未提交的技能名重置丢失），直接点击“预览并提交”。
- **北森 Classic 日期格式硬约束**：日期必须为斜杠格式 `YYYY/MM/DD`（如 `2027/06/01`），填入横杠格式 `YYYY-MM-DD` 会直接触发 `日期格式不正确` 校验报错。已提交申请需修正时，在 `/Portal/Apply/Index` 点击「编辑申请」即可无损修订。
- **大易系统（如宇视）投递与站点锁定**：投递按钮内联绑定 `checkPositionRegist()`，需通过 JS 执行触发；**首投永久锁定面试站点（datamsg=180001）**，第一志愿必须选目标城市站点（如杭州站）；家庭成员必填三项（姓名/关系/单位）需真实亲属信息，严禁编造。
- **Moka 系统提交行为与 Base 核验**：职位列表中显示的地点可能是总部或大区，真实 Base 必须进入岗位详情或网申表单下拉中核实；某些站点的「预览并提交」在表单合法时会自动直接跳转落库，不能假设一定停在独立确认页。
- **智联招聘专区前端失效**：部分第三方专区的前端立即投递按钮可能因批次策略调整而处于失效/无响应状态，核验无响应后需向远端看板报告封锁归档，避免无限重试。

不同北森门户的路由及登录入口不同；不能保证短信/微信入口或跨门户登录状态通用。

## 其他实际门户经验

- 个别 Moka/北森门户在「预览并提交」或验证码完成后直接创建申请；最早可能提交前保存断点，之后先核验官方记录，不因未看到独立确认按钮就重复点击。
- 分区保存的表单按当前页面正常保存每节并重新打开核对；附件、照片及家庭信息只按实际要求和已有授权处理，不调用网站私有状态或提交 handler。
- 月份控件可能以每月 1 日作为内部占位；区分仅显示月份与对外显示的具体日期。若正式字段或预览/记录出现与已确认资料冲突的事实且不能修正，暂停并报告。独立附件解析展示的旧值不等于正式字段；用户已要求保留旧 PDF 时按原范围处理并说明差异，不能宣称附件已改。用途不明先只读查清，不试提交获取预览。

## 北森老版、应届生 xyz

- 原生 select/input 按正常键盘、选择器操作；控件属于原生也不等于所有模板都接受脚本直接赋值。
- 分步表单每步检查新增必填；未知高中、排名、证件等不编造。
- iframe 上传需在框内确认服务器接收；附件选中不等于上传或投递成功。
- 注册密码、异常登录或工具不支持的验证交用户处理，不反复试密码。

## 飞书（atsx / ud）

| 现象 | 检查与处理 |
|---|---|
| 初始字段、配额或城市上限不完整 | 等当前岗位配置及账号数据加载完成；`document.readyState=complete` 不证明异步表单已就绪 |
| 有「解析并覆盖」但没填入 | 检查该控件是否被固定页脚覆盖，确认命中点后正常点击；解析前保存已有修订快照 |
| 多选城市没有选中 | 打开后用输入过滤，再正常选项点击或 ArrowDown/Enter 确认；以已选标签为准，不以搜索框文字为准 |
| 翻页后还是同一批岗位 | 检查实际分页控件、页码与岗位 ID；`?page=` 不一定有效，列表签名不变就停止重复采集 |
| 研发标题却分类为算法 | 按用户红线同时检查职类，不能只看标题 |

## 验证码与频控

控件的**类型判定与归属**以 [safety-gates.md](safety-gates.md)「验证码边界」为唯一真源（点选型 agent 可做、滑块/短信/图形码交人、失败一次即停）；本节只讲排障。

只使用网站正常验证入口及当前工具允许的交互；需要人工接管就保持页面并说明下一步。失败后依据实际提示做有限尝试，不能循环刷新、伪造 token、自挂验证实例、使用拟人轨迹绕过风控或重放认证请求。

短信发送先确认是否真的发出；已授权的同步服务还需校验新消息的服务/接收账号/时间，不能拿任意更大 ID 的短信试登录。发生频控停止重发，恢复时间以网站为准。

## 浏览器/CDP

| 现象 | 检查与处理 |
|---|---|
| beforeunload/原生离开提示 | 读取提示；只有明确允许放弃该未提交草稿时才确认离开。不要盲发 Enter 给整个浏览器 |
| 页面超时或会话失效 | 先核查提示和目标状态；保存字段/断点后才尝试刷新，不能假定网站会自动存草稿 |
| 单个任务标签仍无响应 | 可创建一个恢复标签并复用登录；保留旧页，在新页核验状态。别关最后一页、批量关页、杀浏览器或替换 profile |
| 元素失效 | 重读页面并重新定位，旧坐标、旧引用不复用 |
| Windows UI 自动化需要兜底 | 优先已有 browser 工具；确需 computer-use 时先读其技能，遵守目标窗口、登录及确认限制，不自行写 PowerShell 鼠标/键盘注入 |
| 浏览器工具不可用 | 报告实际错误与可接管步骤；不猜窗口/点击坐标，不把连接超时说成投递失败 |
| 固定资料目录与实际 CDP 浏览器不一致 | 用只读自检确认浏览器进程/端口和目录；保留当前会话并报告，不强关浏览器或迁移 cookie。下次正常启动时使用已配置的稳定资料目录，必要时重新登录。 |

用户明确只投某公司时，阻塞不授权自动换公司；保存本地断点，报告下一步。未来继续仍先查询已有申请。
